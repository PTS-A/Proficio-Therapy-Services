1.0 EXECUTIVE SUMMARY & ARCHITECTURAL VISION

1.1 Business Problem & Strategic Imperative

Healthcare credentialing and payer enrollment represent the primary financial gating mechanisms for multi-specialty therapy organizations. Clinicians cannot bill commercial health plans, Medicaid HMOs, or state Regional Centers until they successfully pass two rigorous administrative gauntlets:

  • Individual Clinician Credentialing: Verification of primary source credentials (state board licenses, national board certifications, NPI verification, DEA/malpractice coverage, and CAQH ProView attestation) culminating in formal payer credentialing committee approval.
  • Legal Facility Group Linking: Execution of contract attachments and roster updates linking the provider's Type 1 individual NPI to the operating entity's Type 2 group NPI, billing Tax Identification Number (TIN), and physical clinic location.

Without centralized software, credentialing teams historically experienced average turnaround delays exceeding 120 days, frequent claim rejections due to unlinked facility locations, and missed CAQH 120-day re-attestation deadlines. This system unifies all three practice entities into one real-time operational engine.

1.2 Core Architectural Objectives

  • Turnaround Acceleration: Reduce average credentialing cycle time from 120+ days to under 45 days.
  • Dual-Verification Enforcement: Hard validation gates ensuring no clinician is released for billing until both payer approval and facility linking are confirmed.
  • Real-Time Transparency: Unified management dashboards with 10 executive KPIs and dynamic 30–120+ day aging distribution.
  • Audit Integrity: Immutable collaboration comments and stage transition histories with explicit author and timestamp tracking.

4.0 END-TO-END OPERATIONAL LIFECYCLE WORKFLOWS

4.1 Step 1: Initial Clinician Onboarding Intake

Collects baseline demographic and professional information:

  • Field 1: Clinician Full Name & Professional Credentials (e.g. MS, BCBA, CCC-SLP, OTR/L).
  • Field 2: Primary Contact Phone Number and Work Email Address.
  • Field 4: Primary Office Location & Service Hub (e.g. San Jose, Fremont, Pleasanton, San Mateo, Sacramento).
  • Field 5: Clinical Discipline Selection (Applied Behavior Analysis, Speech Therapy, or Occupational Therapy).
  • Quick Presets: One-click sample clinician buttons for rapid demonstration and validation testing.

4.2 Step 2: Provider Verification & Start Credentialing

Presents a top summary banner confirming Step 1 details. Features a prominent, centered "Start Credentialing" action button. Gathers:

  • Field 3: Individual 10-Digit National Provider Identifier (NPI) & State Professional Board License Number with Expiration Date.
  • Field 6: CAQH ProView ID Number and Primary Healthcare Provider Taxonomy Code.
  • Supporting Documents Subtab: Table view displaying linked verification items (State License, Board Certification, Malpractice Insurance COI, CV, PAVE Proof) with inline modal to append new document URLs.

4.3 Step 3: Payer Application Bundling & Collaborative Comments

Allows the coordinator to select target insurance payers from a multi-select grid (Kaiser, Blue Shield, Optum/UHC, Aetna, Cigna, Anthem, Magellan). Incorporates a non-prominent secondary "Add Comment" button that expands an inline note form to log specialist observations, reference numbers, or coordinator handoffs with automatic author attribution.

4.4 Step 4: Post-Add Confirmation & Billing Group Linking

Executes an atomic persistence routine across all system entities. Renders a comprehensive verification summary card confirming profile synchronization. Concludes with a prominent Provider Linking section containing a plus sign (+) button to map the clinician to the group practice TIN, clinic location NPI, and supervising provider.

5.1 Collections Overview

Relational-in-NoSQL Architecture: The database maintains strict referential integrity between human resources, clinical credentials, payer applications, document attachments, and audit trails using standardized foreign key fields.

7.0 BUSINESS LOGIC, AGING & AUTOMATION ENGINE

7.1 Dynamic Aging Classification

The system calculates aging dynamically using the formula: Math.floor((Date.now() - Date.parse(submissionDate)) / (1000 * 60 * 60 * 24)).

  • 0–30 Days (On Track): Normal processing interval. Routine confirmation of document completeness.
  • 31–60 Days (In Progress): Payer committee evaluation phase. Specialists perform first milestone outreach.
  • 61–90 Days (Aging): Approaching commercial standard SLA threshold. Automated amber alert displayed on specialist queue.
  • 91–120 Days (Critical): Overdue milestone. Elevated to weekly executive escalation log.
  • 120+ Days (Severe Delay): Urgent operational intervention required. Flagged for health plan network manager escalation.

9.0 SECURITY ARCHITECTURE, RBAC & FIRESTORE RULES

9.1 Role-Based Access Control (RBAC)

  • Administrator: Unrestricted read/write across all collections, configuration of users, and audit trail inspection.
  • Credentialing Specialist: Create and update applications, upload verification documents, add collaborative notes, and manage provider rosters.
  • Credentialing Manager: Full operational oversight, approvals verification, escalation handling, and compliance report generation.
  • Read-Only Stakeholder: Read-only access to executive dashboard, aging charts, and high-level reports.

9.2 Firestore Security Hardening

All database routes enforce input validation and regex checks on document identifiers:

function isValidId(id) { return id is string && id.matches('^[a-zA-Z0-9_-]{1,64}$'); } match /employees/{employeeId} { allow read, write: if request.auth != null && isValidId(employeeId); } match /clinical_staff/{staffId} { allow read, write: if request.auth != null && isValidId(staffId); } match /applications/{appId} { allow read, write: if request.auth != null && isValidId(appId); }

10.0 NON-FUNCTIONAL, LATENCY & RELIABILITY SLAS
